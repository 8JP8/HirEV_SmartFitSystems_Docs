App.config Configuration Guide

This guide documents the App.config appSettings used by the Hi-rEV SmartFitSystems WPF application. The project copies App.config to the output directory, and the application reads it through System.Configuration.ConfigurationManager.AppSettings.

Most numeric geometry and motion values are in millimeters unless the setting name or description says otherwise. Boolean values should be True or False; the code is generally case-insensitive, but keeping the existing capitalization makes changes easier to review. Decimal values should use . as the separator because many readers parse with invariant culture.

Note: Settings with their unit tagged with Units depend on the Units configuration key. If the Units key is changed (e.g., to inch), these values are interpreted in the configured unit rather than absolute millimeters.

How Configuration Is Applied

  • App.config is the source configuration in the project root. At build time it is copied to the executable output because the project marks it with CopyToOutputDirectory=PreserveNewest.
  • The runtime executable config may diverge from the root App.config when the application saves settings through the UI. If behavior differs between a developer build and the checked-in file, inspect the .exe.config beside the built executable.
  • Scanner_Type links this file to ScannerConfigurations.xml. When the selected scanner name exists in ScannerConfigurations.xml, scanner preset geometry such as FOV and standoff is loaded from that XML file. The Scanner_FOV_X, Scanner_FOV_Y, Scanner_Standoff, Scanner_MinStandoff, Scanner_MaxStandoff, and Scanner_AspectRatio values in App.config act as fallbacks when the named scanner preset cannot be loaded.
  • CMM_Type has a fallback role. The main measuring mode normally comes from protected user configuration (CMM_MeasuringType), and CMM_Type is used when that protected value is missing or invalid.

Scanner Selection And Geometry

These settings define the scanner model, basic field of view, standoff range, and base scan-line generation. For a valid Scanner_Type, values from ScannerConfigurations.xml are authoritative for scanner geometry.

Key Current value Type / unit What it controls
Scanner_Type ScannerName1 Scanner preset name Selects a scanner entry from ScannerConfigurations.xml. If no matching scanner exists, the app builds a fallback scanner from the Scanner_FOV_*, standoff, aspect ratio, and raycasting tolerance values in this file.
Scanner_FOV_X 100.0 Millimeters Units Fallback scanner field-of-view width at optimal standoff. Larger values let each pose see more surface, but can overstate coverage if the physical scanner is narrower.
Scanner_FOV_Y 75.0 Millimeters Units Fallback scanner field-of-view height at optimal standoff. Keep this consistent with Scanner_AspectRatio and the physical scanner preset.
Scanner_Standoff 150.0 Millimeters Units Fallback optimal distance from scanner to part surface. This is the target working distance used when a scanner preset is not loaded.
Scanner_MinStandoff 100.0 Millimeters Units Fallback closest valid scanner-to-surface distance. Coverage candidates closer than this can be rejected when Scanner_CoverageUseMinStandoff is enabled.
Scanner_MaxStandoff 200.0 Millimeters Units Fallback farthest valid scanner-to-surface distance. Candidates beyond this range are treated as out of range for scanner coverage.
Scanner_ScanlineOverlap 0.3 Ratio, 0.0 to 1.0 Overlap between adjacent scanner lines or passes. Higher values improve redundant coverage but increase the number of generated positions and path length.
Scanner_PointSpacing 1.0 Millimeters Units Distance between generated points along a scan line. Smaller spacing creates denser scanner paths and smoother coverage at higher computation and visualization cost.
Scanner_AspectRatio 1.33 Ratio Fallback field-of-view aspect ratio (FOV_X / FOV_Y). Used with fallback scanner geometry; keep synchronized with the selected physical scanner.
Scanner_RaycastingEnabled True Boolean Enables raycasting-based filtering and visibility checks for scanner field-of-view coverage. Disabling it can speed planning but removes important visibility validation.
Scanner_RaycastingTolerance 0.5 Millimeters Units Tolerance used in scanner raycasting visibility checks. Larger values are more forgiving around mesh precision errors; smaller values are stricter but can reject borderline visible surfaces.
Scanner_MaxDistanceGap 5.0 Millimeters Units Maximum tolerated distance gap between the part surface and scanner range limit during coverage checks. Increase only when valid scan poses are being rejected near range boundaries.
Scanner_OrbitalRadius 2.0 Multiplier Multiplies standoff for legacy orbital interpolation sizing. Higher values keep scanner motion farther from the part, improving clearance but increasing travel.
Scanner_OrbitalWaypoints 6 Count Number of intermediate waypoints between scanner measurement points. More waypoints make smoother movement and visualization, but increase path size.
Scanner_ProximityOrdering True Boolean Orders scanner measurement positions with a nearest-neighbor heuristic to reduce travel distance. Disable only when preserving generation order is useful for debugging.
Coordinates_RelativeToPart True Boolean Exports or generates coordinates relative to the part origin instead of the Eyeshot scene origin. Use True for part-local programming; use False when absolute scene coordinates are required.

Tuning Profiles

Use these as starting points rather than fixed recipes.

Goal Main settings to adjust
Higher inspection accuracy Lower PathPlanning_MinPointDistance, PathPlanning_EdgePointMinDistance, and PathPlanning_GridSpacing; keep PathPlanning_PreserveCorners, PathPlanning_ValidateControlPointBoundaries, and PathPlanning_EnableGridGeneration enabled.
Faster probe paths Raise point spacing values, reduce grid generation density, and keep costly validation settings such as PathPlanning_EnableCollisionValidation and PathPlanning_EnableSegmentCollisionValidation disabled unless required.
Better scanner coverage Raise Scanner_MinCoveragePercent, Scanner_FibonacciSamples, and candidate amplification values; keep raycasting and verification enabled. Expect slower generation.
Faster scanner planning Lower Scanner_FibonacciSamples, reduce amplification, increase verification grid spacing, and keep early-exit/range-skipping options enabled.
Safer motion around complex parts Increase approach/retract offsets and safety margins, enable shell-based planning, and consider enabling segment or jump collision validation after testing the performance impact.
