Descrição detalhada

Static utility class for detecting and classifying holes from extracted CAD faces. This class analyzes cylindrical and conical faces to identify hole features, matching them to standard metric thread specifications.

The hole detection algorithm:

  1. Filters faces to cylindrical/conical types
  2. Groups faces that share the same axis and radius
  3. Validates hole geometry (depth, top/bottom surfaces)
  4. Classifies holes against standard metric thread sizes
  5. Reports non-hole faces separately

Enhanced features:

  • Tolerances for small vertical deviations in complex surfaces
  • Support for both tap drill sizes and clearance holes
  • Progress reporting for long operations
  • Robust handling of non-standard geometries

bool HirEV_SmartFitSystemsApp.Modules.HoleDetector.CanConvertToHole ( CADFace face1,
CADFace face2 )
static

Determines whether two faces can be converted into a hole feature. This validation method checks geometric and type requirements before hole creation.

Parâmetros
face1The first face to validate. Can be null (returns false). Must be cylindrical or conical type for hole conversion.
face2The second face to validate. Can be null (returns false). Must be cylindrical or conical type with similar radius to face1.
Retorna
true if both faces meet hole conversion requirements:
  • Neither face is null
  • Faces have different global indices (not the same face)
  • Both faces are cylindrical or conical type
  • Both faces have valid positive radii
  • Radii differ by less than 0.2mm (RADIAL_TOLERANCE) false otherwise.

Validation checks performed:

  1. Null checks for both faces
  2. Different face indices (prevents self-pairing)
  3. Type validation (Cylindrical or Conical only)
  4. Radius extraction and validation
  5. Radius similarity check (within 0.2mm)

This is typically called before attempting hole creation to avoid creating invalid holes or exceptions during geometry calculation.

Common rejection reasons:

  • Null faces (incomplete face extraction)
  • Same face selected twice (UI error)
  • Non-cylindrical faces (planar, spherical, etc.)
  • Drastically different radii (not part of same hole)
  • Zero or negative radii (degenerate geometry)

Creates a CADHole object from two cylindrical/conical faces representing a hole feature. This is a convenience wrapper around CreateHoleFromFaces for manually specified face pairs.

Parâmetros
face1The first face of the hole pair. Must be cylindrical or conical type. Typically represents one side of the hole (e.g., inner surface).
face2The second face of the hole pair. Must be cylindrical or conical type with similar radius to face1. Typically represents the other side of the hole (e.g., outer surface or continuation).
holeIdUnique identifier to assign to the created hole. Used for tracking and reference. Should be unique across all holes in the model.
allFacesThe complete list of all faces in the model. Used to find adjacent top/bottom surfaces for accurate hole geometry calculation (entry/exit points, depth).
Retorna
A CADHole object containing:
  • Geometric properties (axis, radius, depth, top/bottom positions)
  • Classification (standard thread type if matched)
  • References to constituent faces
  • Color and metadata Returns null if faces cannot form a valid hole.

This method delegates to CreateHoleFromFaces after wrapping the two faces in a list. Validation is performed by CreateHoleFromFaces.

Common use case: Manual hole creation from user-selected cylindrical face pairs via UI context menu or programmatic conversion.

◆ IdentifyStandardHoleType()

string HirEV_SmartFitSystemsApp.Modules.HoleDetector.IdentifyStandardHoleType ( double diameter)
static

Identifies and classifies a hole against standard metric thread specifications. Matches the measured diameter to tap drill or clearance hole standards.

Parâmetros
diameterThe measured diameter of the hole in millimeters. Should be the average diameter from cylindrical face analysis. Must be positive and not NaN for valid classification.
Retorna
A string identifying the hole type:
  • Standard thread designation (e.g., "M6", "M10") if diameter matches tap drill size within tolerance
  • Clearance designation (e.g., "M6 Clearance") if diameter matches nominal + 0.5mm
  • "Custom X.XXmm" for non-standard diameters
  • "Unknown" for invalid input (NaN, negative, or zero)

Classification algorithm:

  1. Validate input (reject NaN, negative, zero)
  2. Search for tap drill size match (within DIAMETER_TOLERANCE = 0.5mm)
  3. If no tap drill match, search for clearance hole match (nominal + 0.5mm ± tolerance)
  4. If no match found, report as custom with measured diameter

Standard classifications:

  • Tap drill: Diameter matches standard tap drill size for internal threads Example: 5.0mm → "M6" (tap drill for M6 internal thread)
  • Clearance: Diameter matches nominal bolt diameter plus 0.5mm clearance Example: 6.5mm → "M6 Clearance" (M6 bolt with standard clearance)
  • Custom: Non-standard diameter reported with 2 decimal precision Example: 7.35mm → "Custom 7.35mm"

Tolerance handling:

  • DIAMETER_TOLERANCE = 0.5mm allows for manufacturing variations
  • Clearance holes use ±0.3mm tolerance around nominal+0.5mm
  • Tap drill matches take priority over clearance matches

Supported range: M1.6 (1.25mm) to M56 (50.0mm)

◆ holes

List<CADHole> HirEV_SmartFitSystemsApp.Modules.HoleDetector.holes
static

Detects and extracts hole features from a collection of CAD faces. This is the main entry point for hole detection, processing all faces and identifying valid holes.

Parâmetros
allFacesThe complete list of extracted CAD faces to analyze. Must include face type classification. Only cylindrical and conical faces are considered for hole detection.
progressCallbackOptional callback for progress updates. Receives two parameters:
  • percentage (int): Progress from 0-100 representing detection phase completion
  • holeCount (int): Number of holes successfully detected so far Progress phases: 10% filtering, 30% grouping, 50-100% validation
Retorna
A tuple containing:
  • holes (List<CADHole>): List of validated hole features with geometry, classification, and metadata
  • nonHoleFaces (List<CADFace>): Faces that don't belong to holes (includes non-cylindrical faces and rejected hole candidates)

Detection algorithm phases:

  1. Filter cylindrical/conical faces (10% progress)
  2. Group faces by shared axis and radius (30% progress)
  3. Create and validate hole objects (50-100% progress)
  4. Classify against standard metric threads
  5. Separate processed faces from non-hole faces

Validation criteria:

  • Hole must consist of exactly 2 faces (inner and outer surfaces)
  • Depth must exceed MIN_HOLE_DEPTH_TOLERANCE (0.01mm)
  • Faces must share axis within RADIAL_TOLERANCE (0.2mm)
  • Faces must have similar radius within tolerance

Rejected holes:

  • Single-face features (surface pockets)
  • Zero-depth features (artifacts)
  • Misaligned face pairs
